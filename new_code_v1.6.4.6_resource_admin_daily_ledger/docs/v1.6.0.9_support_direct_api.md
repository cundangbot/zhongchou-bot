# v1.6.0.9 客服回复换接口说明

这版不再继续只依赖 aiogram 的 `bot.send_message()` / `bot.copy_message()` 给用户投递客服回复，而是默认改成原生 Telegram Bot API HTTP 调用。

## 1. 新投递链路

管理员回复客服工单后，程序会优先调用：

- `sendMessage`：发送文字回复，或媒体回复前置工单头消息。
- `copyMessage`：复制管理员发在审核群里的图片、视频、文件、语音等消息给用户。
- `deleteMessage`：媒体复制失败时，自动清理已经发出的前置头消息，避免用户只看到半截内容。

相关代码：

- `app/services/telegram_direct.py`
- `app/handlers/start.py`

## 2. 配置项

`.env.example` 已新增：

```env
BOT_API_BASE_URL=https://api.telegram.org
SUPPORT_DELIVERY_MODE=direct_http
SUPPORT_DIRECT_API_TIMEOUT_SECONDS=15
SUPPORT_DELIVERY_FALLBACK_TO_AIOGRAM=true
```

说明：

- `direct_http`：默认模式，优先走原生 Bot API HTTP。
- `direct_only`：只走原生接口，不再退回 aiogram。
- `aiogram`：临时退回旧投递方式。
- `BOT_API_BASE_URL`：支持自建 `telegram-bot-api` 服务地址，例如 `http://telegram-bot-api:8081`。

## 3. 用户主动拉取兜底

用户提交客服小纸条后，现在会看到：

- `🔄 查看小掌柜回复`
- `💬 继续联系客服`
- `📋 返回我的众筹`

管理员回复内容会写入 `contact_tickets.admin_reply`。如果用户手机没有弹出推送，用户可以点「查看小掌柜回复」直接从数据库里的工单记录读取回复。

这相当于把客服答复从“只靠推送”改成：

1. 原生 Bot API 主动推送。
2. aiogram 可配置兜底。
3. 用户主动拉取工单回复。

## 4. 管理群回执

客服发送成功后，审核群回执会显示实际投递通道，例如：

```text
投递通道：原生 Bot API HTTP 通道
```

如果原生接口失败后 aiogram 兜底成功，回执会显示切换原因，方便继续排查到底是接口层、网络层，还是封装层问题。
