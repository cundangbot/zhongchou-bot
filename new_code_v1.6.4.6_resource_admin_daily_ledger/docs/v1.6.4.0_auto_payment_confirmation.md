# v1.6.4.0 自动支付确认说明

## 新流程

1. 用户先在拼车机器人生成待付车票，再点击原支付链接付款。
2. Telethon 商家账号收到购买成功通知。
3. 系统从通知中提取 VP 系统单号、人民币金额、商品名称和支付方式。
4. 系统把 VP 发送给 faka 查询机器人，获取支付通道、支付单号、状态、金额、商品、Telegram 用户 ID 和下单机器人。
5. 两份消息交叉核对通过后，按 Telegram 用户 ID + 应付金额寻找本地待付车票。
6. 只有一个候选车票时自动验票并锁位；存在多个同额候选时停止自动绑定，提醒用户选择。

## 为什么不能只按昵称绑定

购买成功通知中的昵称可能重复、变化或包含空格，不能作为唯一身份。自动流程只使用 faka 返回的 Telegram 数字用户 ID 绑定本地订单。

## 安全边界

静态支付链接本身不携带本地车票 ID。因此，同一用户同时存在多张相同金额的待付车票时，无法从支付平台消息确定用户实际点击的是哪张车票。系统不会按“最新订单”猜测，以免把付款绑定到错误项目。

若未来支付平台支持动态创建订单或回调透传，可把本地 `T.xxx` 作为商户订单附加字段，实现多待单场景下的完全自动绑定。

## 配置

```env
PAYMENT_AUTO_CONFIRM_ENABLED=true
PAYMENT_CONFIRM_BOT_USERNAME=@jingpinhybot
PAYMENT_EXPECTED_PRODUCT_KEYWORDS=车位支付链接
```

- `PAYMENT_CONFIRM_BOT_USERNAME`：发送“购买成功”通知的真实机器人用户名。
- `FAKA_BOT_USERNAME`：接收 VP 并返回订单详情的查询机器人。
- `EXPECTED_FAKA_ORDER_BOT`：订单详情中预期的“下单机器人”。
- `PAYMENT_EXPECTED_PRODUCT_KEYWORDS`：可选商品名白名单，多个关键字用英文逗号分隔。

## 失败兜底

自动监听、查单或核对失败时，原有用户手动提交 VP 的流程继续可用。自动流程不会因为昵称、金额或商品不一致而强行入账。
