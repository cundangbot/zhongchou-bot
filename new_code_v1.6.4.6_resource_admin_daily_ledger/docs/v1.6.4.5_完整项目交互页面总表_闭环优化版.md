# 0. 整体业务流程图

```text
用户进入机器人
├─ 热门众筹 → 查看项目 → 点击上车 → 生成待付车票 → 支付 → 自动核验
├─ 发起众筹 → 填资料 → 管理员审核 → 频道发布 → 发起人双车位支付 → 正式拼车
└─ 我的众筹
   ├─ 待付车票
   ├─ 已上车票
   ├─ 退款车票
   ├─ 我是车主记录
   ├─ 我的宝贝资源
   └─ 联系小掌柜

自动支付：
购买成功通知 → 精确识别四种商品 → 提取 VP → faka 查询一次
→ 保存已核实付款记录
├─ 唯一待付票：自动绑定
├─ 多张匹配待付票：用户选择车票
└─ 没有待付票：用户选择可恢复项目

项目满员：
├─ 发起人垫付/已有资源 → 通知车主上传资源
└─ 平台代购 → 通知车主填写购买渠道 → 管理员上传资源

资源审核通过 → 给所有已支付用户开放领取
```

# 7. 自动支付识别

## 7.1 接受的四种商品

```text
车位支付链接[拼车单车位30元支付链接]
车位支付链接[拼车单车位60元支付链接]
车位支付链接[发起人双车位60元支付链接]
车位支付链接[发起人双车位120元支付链接]
```

对应含义：

```text
拼车单车位30元 → 30 元普通车位或满员补票
拼车单车位60元 → 60 元普通车位或满员补票
发起人双车位60元 → 30 元项目的发起人双车位
发起人双车位120元 → 60 元项目的发起人双车位
```

## 7.2 自动处理顺序

```text
收到“购买成功！”
→ 精确识别商品
→ 提取 VP
→ 同一 VP 加锁
→ faka 查询一次
→ 核对系统单号、支付状态、商品、金额、支付方式、下单机器人、Telegram 用户 ID
→ 保存“已核实付款记录”
→ 本地绑定
```

其他商品不会提取 VP，也不会查询 faka。
