# v1.6.2.3 车主重开、退款小票、手动补订单闭环修复

## 本版重点

1. 车主记录中，已取消/退款中/退款完成的项目会出现「重新拼车」按钮。
2. 重新拼车不会覆盖旧项目，会克隆旧项目资料生成新的待审核项目，并发送到审核群。
3. 管理员审核通过新项目后，仍走原发起众筹流程：车主收到双车位预付通知，验票后项目进入公开拼车。
4. 管理后台「退款小票」不再只显示当天记录，而是显示所有未完成退款。管理员点击确认已退款后才从待办消失。
5. 管理员确认退款完成后，机器人会私信通知用户；若同项目所有退款都完成，项目状态自动收尾为 refund_completed。
6. 手动补票改成「补订单」闭环：没有待付车票也可以补。管理员输入“用户ID VP系统单号”，系统会创建已支付车票并接到用户身上。
7. 新增命令 `/add_order P.项目 用户ID VP系统单号`，用于跳过按钮直接给用户补订单。

## 手动补订单规则

- 如果项目还有待付车票，可以点具体车票补 VP。
- 如果没有待付车票，管理员仍可输入：`用户ID VP系统单号`。
- 系统会创建一张已支付车票，挂到对应 user_id + project_id。
- 会执行普通已支付效果：写 ResourceAccess、更新人数/满员状态、写资金流水。
- 众筹完成或资源审核通过后，该用户能正常领取资源。

## 退款小票规则

- `admin:list:refunds` 显示所有 `pending_info` / `pending_admin` 退款，不再按当天过滤。
- 用户提交退款资料后，退款单状态为 `pending_admin`，管理员确认后变为 `refunded`。
- 对应 PaymentOrder 变为 `refunded`。
- 如果项目下所有退款都完成，项目从 `refund_pending` 转为 `refund_completed`。
