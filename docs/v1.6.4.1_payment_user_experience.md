# v1.6.4.1 支付用户交互说明

## 用户主流程

- 生成待付车票后，主按钮改为「💳 立即支付」。
- 自动验票开启时，不再要求用户付款后返回并手动提交 VP。
- 用户可通过「🔄 已付款，查看识别结果」查看本地入账状态。
- 「🧾 自动识别失败？提交 VP」仅作为异常兜底。
- 自动验票成功后，主动推送项目、车票、VP、支付方式和金额，并提供「查看已上车票」入口。

## 异常交互

- 同一用户存在多张同金额待付车票：直接展示对应项目按钮，用户点击后立即绑定，不再要求复制 VP。
- 找不到待付车票：展示「选择要绑定的拼车」，再次核对付款账号和金额后恢复绑定。
- 用户误输支付单号或错误 VP：错误卡片展示实际核对原因，并明确只接受 VP 系统单号。
- 取消待付票：增加二次确认，明确提示已付款后不要取消。

## 核对安全

- 使用 faka 返回的 Telegram 数字用户 ID 认领付款，不使用昵称。
- 核对 VP 系统单号、已支付状态、人民币金额、商品名称、支付方式。
- 启用 `PAYMENT_EXPECTED_PRODUCT_KEYWORDS` 时，商品必须命中允许关键词。
- 多张同金额待付票不会按“最新订单”自动猜测。
- VP 重复使用仍由原有幂等和重复订单检查拦截。

## 静态检查

- `python -m compileall -q app scripts`：通过。
- `python scripts/check_fstring_compat.py .`：通过。
- 顶层循环导入静态检查：通过。
- 支付卡片、待付详情和手动 VP 兜底文案渲染测试：通过。
