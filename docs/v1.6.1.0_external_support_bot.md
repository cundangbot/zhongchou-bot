# v1.6.1.0 客服入口外置到 @jingpinhybot

## 背景

原机器人内置客服工单链路已经多次切换投递方式，但用户侧仍反馈无法稳定收到客服回复。为避免继续在同一条链路上消耗时间，本版本不再让用户进入本机器人的客服状态机，而是将所有用户侧「联系小掌柜 / 继续联系客服」按钮统一改为打开独立双向客服机器人。

默认目标机器人：`@jingpinhybot`

## 用户侧按钮改动

以下入口全部改为 URL 外跳，不再触发 `support:start:*` callback：

- 我的众筹首页：联系小掌柜
- 验票失败页：联系小掌柜
- 支付异常页：联系小掌柜
- 退款详情页：联系小掌柜
- 工单状态页：继续联系客服
- 客服兜底按钮：继续联系客服

按钮会打开：

```text
https://t.me/jingpinhybot?start=<payload>
```

## 传给 @jingpinhybot 的 start payload

格式：

```text
<SUPPORT_BOT_START_PREFIX>_<source>_<ref_id>
```

默认前缀：`cf`

示例：

```text
cf_generic_0
cf_error_123
cf_refund_8
```

`source` 含义：

- `generic`：通用客服入口
- `error`：验票/支付异常入口
- `refund`：退款详情入口
- `project`：项目详情入口
- `pending`：待付车票入口

> 说明：Telegram bot deep link 的 start 参数长度限制较短，因此这里只传短来源和业务 ID，详细沟通由 @jingpinhybot 内部双向会话承接。

## 兼容旧按钮

旧消息里如果还残留 `support:start:*` callback，用户点击后不会再进入旧客服工单流程，而是显示一个「已切换到独立客服机器人」面板，并附带打开 @jingpinhybot 的按钮。

## 新增配置

```env
SUPPORT_BOT_USERNAME=@jingpinhybot
SUPPORT_BOT_START_PREFIX=cf
```

后续如果要换客服机器人，只改 `.env`：

```env
SUPPORT_BOT_USERNAME=@新的客服机器人
```

## 保留内容

后台历史客服工单、管理员客服列表、旧工单状态查询代码暂时保留，不做删除，避免影响历史数据查看。
