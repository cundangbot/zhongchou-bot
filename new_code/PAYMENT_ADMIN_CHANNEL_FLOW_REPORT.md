# v1.6.4.3 支付异常联络、频道模板与管理交互检查报告

## 1. 支付监听与用户识别

- 购买通知必须包含“购买成功！”或“购买成功!”。
- 必须存在 `商品：` 字段，且去除空白后以 `车位支付链接` 开头。
- 通过商品前缀与配置白名单后，才提取 `VP` 系统单号并向 faka 查询。
- faka 必须返回有效的 Telegram 数字用户 ID，系统才允许向付款用户发送任何自动验票或异常恢复私信。
- 昵称只用于展示，不参与用户绑定。
- “检测到付款但没有待付车票”仅作为异常恢复分支：付款前未占座、待付票过期、误取消或被其他流程处理时才会出现。

## 2. 动态项目展示

用户在多张同额待付票或无待付票恢复页选择项目后，正在验票页动态显示：

```text
选择项目：P.{用户实际选择的项目编号}｜{该项目博主}
```

项目编号和博主都从用户点击的项目按钮对应数据库记录读取，不是固定文案。

## 3. 用户支付交互

待付列表统一为：

```text
💳 待付车票
━━━━━━━━━━━━━━

第 {当前页}/{总页数} 页｜共 {数量} 条

━━━━━━━━━━━━━━
点开对应项目后点击「💳 立即支付」，付款成功会自动验票并主动通知上车。

若已经付款但状态没有更新，可进入车票详情点「🔄 已付款，查询状态」。
```

已上车票详情仅保留资源领取与返回按钮，不再显示“查看退款进度”。退款记录仍在独立的“退款车票”入口处理。

## 4. 支付异常联系用户

以下管理员通知均带按钮：

```text
💬 查询用户并联系
```

覆盖：

- faka 查单失败；
- 购买通知与 faka 双消息核对失败；
- faka 缺少用户 ID/金额等关键字段；
- 自动绑定失败；
- 自动入账异常；
- 需要用户选择绑定项目。

管理员点击后，系统重新通过 faka 查询 VP 对应的 Telegram 数字用户 ID；确认后在 `SUPPORT_ADMIN_ID` 对应管理员私聊中建立或恢复客服会话。faka 无法返回有效数字用户 ID 时不会猜测用户，也不会错误私信。

## 5. 管理员主动联系命令

“回复客户”说明新增：

```text
/contact 用户ID
/msg 用户ID 要发送的内容
```

- `/contact`：按 Telegram 数字用户 ID 打开/重新建立客服会话。
- `/msg`：按用户 ID 立即发送消息，同时建立可继续回复的客服会话。
- 用户即使此前点击“结束对话”，也会创建新的开放工单，不依赖旧工单仍处于打开状态。

## 6. 管理项目交互

项目详情新增：

```text
🧩 生成拼车模板
```

该按钮会在公开频道重新发送一条独立、可持续更新的拼车面板，并把项目后续人数、满员、补票和取消状态更新目标切换到新消息。

已从项目详情及常用工具的可见按钮中移除：

- 手动取消项目；
- 待付车票/绑定待付车票；
- 支付闭环检查；
- 同步进度/同步项目。

相关底层维护命令未删除，避免数据库或历史订单异常时失去应急修复能力，但普通管理交互中不会显示，减少误触。

## 7. 频道发布顺序

审核通过后的发布顺序改为：

1. 向公开频道发送投稿详情及媒体；
2. 再向公开频道发送独立拼车模板和上车按钮；
3. 后续只编辑独立拼车模板的进度与状态。

运行时不再依赖频道评论区或讨论组转发。旧数据库中的 `discussion_*` 字段只为兼容既有数据库结构保留，新流程会主动清空，不再读取或发布到评论区。

## 8. 无调用代码清理

- 删除评论区运行服务及对应配置项；
- 删除被移除按钮对应、已经没有入口的旧回调；
- 删除无引用的旧取消项目辅助链路、旧频道评论辅助代码与无用导入；
- 检查全项目顶层私有辅助函数，没有发现零引用函数；
- 保留路由装饰器处理函数、调度任务、迁移兼容字段及实际被间接调用的功能。
