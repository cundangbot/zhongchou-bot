# v1.6.0.7 客服双向桥优化说明

## 解决的问题

原客服链路只有一种入口：管理员点「回复用户」后，必须按 ForceReply 提示回复。实际运营时容易遇到：

- 管理群隐私模式、未正确回复提示消息，导致机器人收不到管理员回复。
- 用户屏蔽机器人、未启动机器人、账号不可用时，管理群只看到泛化错误，不知道怎么处理。
- 工单卡片和回执分散，管理员想继续补发时需要反复点按钮。

## 新增能力

1. 统一投递核心
   - 按钮回复、命令回复、直接回复工单卡片都走同一个 `_send_support_reply_core`。
   - 成功后统一更新工单状态、发送管理群回执、同步原工单卡片。
   - 失败后把友好原因写入 `ContactTicket.last_error`，工单保留为待回复。

2. 双向客服桥
   - 管理员可以直接回复管理群里的工单卡片或送达回执，机器人会自动解析 `S.001` 并投递给用户。
   - 支持文字、图片、视频、文件、语音等消息。

3. 命令兜底
   - `/reply S.001 回复内容`
   - `/sreply S.001 回复内容`
   - 也可以回复某张工单卡片发送：`/reply 回复内容`

4. 更明确的失败诊断
   - 用户屏蔽机器人/没有启动机器人
   - 找不到私聊会话
   - 用户账号停用
   - Telegram 频率限制
   - 服务器网络/代理异常
   - Token/权限异常

## 使用建议

优先使用「直接回复工单卡片」作为日常客服入口。按钮回复保留给需要明确进入回复状态的场景，命令回复作为最后兜底。

如果失败原因提示用户屏蔽或未启动机器人，需要让用户重新打开机器人并发送 `/start` 后再重试。Telegram Bot API 无法绕过用户屏蔽或未启动会话的限制。
